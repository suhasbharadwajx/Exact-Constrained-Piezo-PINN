# Exact Spatio-Temporal Constrained PINN for Piezoelectric Tensor Discovery

[![Python](https://img.shields.io/badge/Python-3.9%2B-blue.svg)](https://www.python.org/)
[![PyTorch](https://img.shields.io/badge/PyTorch-2.0%2B-ee4c2c.svg)](https://pytorch.org/)

Official code repository for the manuscript:
**"Exact Boundary and Initial Constraints for Physics-Informed Identification of the Shear Piezoelectric Coefficient from Sparse Noisy Wavefield Data"** *(Submitted to Physical Review Applied)*

## Overview
This repository implements a Physics-Informed Neural Network (PINN) designed to solve stiff, strongly coupled electro-elastodynamics. By applying an exact $t^2$ temporal multiplier and a spatial distance function ($\mathcal{D}_{bc}$) directly to the neural network topology, the architecture completely bypasses the initial-state electrostatic inconsistencies inherent to unconstrained soft-penalty formulations. 

Coupled with a rigorous asymptotic dimensional stabilization scheme, the code executes a two-stage (Adam $\rightarrow$ L-BFGS) inverse discovery pipeline to successfully isolate the dimensionless $e_{15}$ shear piezoelectric parameter of a PZT-5H medium. The repository is modularized into two primary frameworks: an exact Method of Manufactured Solutions (MMS) verification, and a discrete numerical cross-validation against noisy COMSOL Multiphysics FE data. To rigorously prevent deceptive optimization shortcuts, both studies evaluate the network against a highly asymmetric, 8-lobe non-polynomial $[1-\cos(2\pi t)]$ transient wavefield.

## Repository Structure

### 1. `MMS-framework/` (Exact MMS Verification)
This directory isolates the network validation against the mathematically exact, noise-free analytical wavefield.
* **`physics.py`**: Contains normalization constants, dimensional scaling, and the exact asymmetric 8-lobe continuous analytical body-force equations.
* **`model.py`**: Defines the `ConstrainedPINN` architecture featuring exact algebraic boundary and initial constraints.
* **`main.py`**: Orchestrates the PDE residuals, computes the loss, and runs the optimization pipeline against the exact synthetic data.

### 2. `FEM-framework/` (Cross-Validation & Noise Analysis)
This directory applies the identical constrained architecture to discrete, full-field finite element data to evaluate performance under realistic measurement and discretization errors.
* **`physics.py` & `model.py`**: The identical continuum physics mapping and constrained neural architecture.
* **`main.py`**: The master orchestration script that loads the FE data, dynamically injects 30 dB Gaussian noise, trains the network, and discovers the $e_{15}$ parameter.
* **`SNR-sweep.py`**: The execution script for the comprehensive noise sensitivity study, running $N=5$ independent stochastic initializations across 9 discrete SNR levels (40 dB down to 0 dB). *(Note: Even with optimized batch sizes and reduced epochs, this comprehensive sweep is computationally intensive and requires approximately 28 hours to complete on a standard NVIDIA Tesla T4 GPU).*
* **`Plot-SNR-sweep.py`**: Generates the final shaded variance band publication graphics (Figure 6) from the sweep results.

### 3. `data/`
* **`FEM-Dataset.txt.zip`**: The uncorrupted transient wavefield dataset extracted directly from the COMSOL Multiphysics solid mechanics and electrostatics simulation. *(Note: Unzip this file into the working directory prior to running the FEM scripts).*

### 4. `Baseline/` (Soft-Penalty Baselines)
This directory trains the same network on the same asymmetric MMS problem, but without any exact constraints. The boundary and initial conditions are enforced only through penalty terms in the loss, which is the formulation the constrained network is compared against. For each seed, the collocation points, the 5,000 noisy observations, the noise realization, and the initial network weights are identical to those of the constrained runs in `Ablation-study/`, so the comparison is paired.
* **`physics.py`**: The same normalization constants and exact 8-lobe wavefield as `MMS-framework/`, with the manufactured body-force and charge-density terms generated by automatic differentiation in float64.
* **`model.py`**: Defines the `SoftPenaltyPINN` architecture, the same $`7 \times 150`$ Tanh network as the constrained model but with no $`\mathcal{D}_{bc}`$ or $`t^2`$ multiplier.
* **`main.py`**: Generates the seeded data, trains both baseline configurations for seeds 1 to 5, and writes the per-run results, the trajectories, and a summary table.
  * **Config A**: Gradient-norm adaptive weights for the two PDE terms, the boundary term, and the two initial-condition terms, updated every 100 steps from the squared gradient norms of the individual loss terms with an exponential moving average of rate 0.1. The data weight is held at $`\lambda \geq 5000`$.
  * **Config B**: Fixed weights $`[1, 1, 5000, 5000, 5000, 5000]`$ in the order [PDE mechanical, PDE Gauss, boundary, initial value, initial velocity, data].
  * Both configurations use the full batch at every step in both optimizer stages: 25,000 collocation points, 5,000 boundary points, 5,000 initial-time points, and 5,000 observations.

### 5. `Ablation-study/` (Spatial vs. Temporal Constraints)
This directory trains four constrained variants on the same seeds and data as `Baseline/`, to separate the effect of the spatial factor, the temporal factor, and the temporal order.
* **`physics.py`**: Identical to `Baseline/physics.py`.
* **`model.py`**: Defines the `AblationPINN` architecture, in which the spatial factor and the power of $`t`$ on each output are switchable.
* **`main.py`**: Trains the four arms for seeds 1 to 5, writes the per-run results and trajectories, and prints the paired differences with respect to C1.
  * **C1**: $`\mathcal{D}_{bc}\,t^2`$ on all three fields (the proposed formulation, no penalties).
  * **C2**: $`\mathcal{D}_{bc}\,t^2`$ on $`u_1`$ and $`u_3`$ but only $`\mathcal{D}_{bc}\,t`$ on $`\phi`$, with no extra penalty.
  * **C3**: Spatial factor $`\mathcal{D}_{bc}`$ only, with soft penalties of weight 5000 on the initial value and the initial rate.
  * **C4**: Temporal factor $`t^2`$ only, with a soft boundary penalty of weight 5000.
  * Each Adam step draws a minibatch of 5,000 collocation points from the 25,000-point pool and uses all 5,000 observations, so these runs use minibatches whereas `Baseline/` uses the full batch.

## Reproducing the Manuscript Results

### Running each study
Run every script from inside its own folder, because the scripts import `physics.py` and `model.py` from the working directory and read or write their files there.

* **MMS verification** (`MMS-framework/`): `python main.py` prints the discovered $`e_{15}`$ and its error, and saves `PRA_Robust_MMS_Graphics.png`.
* **FEM cross-check** (`FEM-framework/`): unzip `FEM-Dataset.txt.zip`, rename the extracted `COMSOL Export.txt` to `FEM-Dataset.txt`, then run `python main.py`. It prints `final_e15,error_pct` and saves `Figure_5_FEM_CrossValidation.png`. (The `__MACOSX` folder created by unzipping can be ignored.)
* **Noise sweep** (`SNR-sweep/`): the sweep lives in its own folder with its own `main.py`, `physics.py`, `model.py`, and copy of the dataset zip. Prepare the dataset in the same way, then run `python main.py`. Each finished run is appended to `SNR-Sweep-Results.csv`, and the shaded-band figure `Figure_6_SNR_Sweep_N5.png` is drawn at the end, so no separate plotting script is needed.
* **Baselines** (`Baseline/`) and **constrained variants** (`Ablation-study/`): run `python main.py`. To split the ten runs of each study over two GPUs, start one worker per GPU:
  ```bash
  CUDA_VISIBLE_DEVICES=0 python main.py 0 2
  CUDA_VISIBLE_DEVICES=1 python main.py 1 2
  ```
  The two arguments are the worker index and the number of workers. Runs already present in the results CSV are skipped, so an interrupted job can be restarted with the same command. When all runs are finished, running `python main.py` once more only prints the summary and redraws the trajectory figure.

### Environment
* The baseline and ablation runs in the manuscript were made on Kaggle with two NVIDIA Tesla T4 GPUs (one worker per GPU) and PyTorch 2.11.0 with CUDA 12.8. All other runs also used NVIDIA Tesla T4 GPUs.
* The scripts also run on CPU, but the full-size runs are slow there.
* The FEM scripts read the dataset with `pd.read_csv(..., delim_whitespace=True)`, which is deprecated since pandas 2.2 and may be removed in pandas 3.0, so use pandas 2.x.
* Peak GPU memory is about 6.2 GB for the full-batch baselines and about 3.5 GB for the ablation arms, which fits on a 16 GB T4.
* In the original runs on two T4 GPUs, one baseline run took about 108 min (A) or 135 min (B), and one ablation run took about 33 min (C1, C2, C4) or 37 min (C3).

### Data and COMSOL model
`FEM-Dataset.txt.zip` contains the unmodified COMSOL export (`COMSOL Export.txt`). The file has `%` header lines, then one row per spatial point with $`x_1`$ in the first column, followed by the three exported quantities for each time: displacement $`u`$ (mm), displacement $`v`$ (mm), and electric potential $`V`$ (V). The export has 5,000 points and 201 times, which gives 603 data columns. The model was built in COMSOL Multiphysics 6.3.0.290 with these settings:
* **Domain**: a 10 mm $`\times`$ 10 mm plane-strain square, with the solid mechanics and electrostatics interfaces coupled through the piezoelectric effect.
* **Material (PZT-5H)**: $`\rho = 7500`$ kg/m$`^3`$; $`c_{11} = 12.6`$, $`c_{13} = 5.3`$, $`c_{33} = 11.7`$, $`c_{44} = 2.30`$ ($`\times 10^{10}`$ Pa); $`e_{31} = -6.5`$, $`e_{33} = 23.3`$, $`e_{15} = 17.0`$ C/m$`^2`$; $`\varepsilon_{11}^S = 1.503 \times 10^{-8}`$, $`\varepsilon_{33}^S = 1.300 \times 10^{-8}`$ F/m. The in-plane term $`c_{12}`$ does not enter the plane-strain equations.
* **Boundaries and initial state**: all four edges fixed ($`u_i = 0`$) and grounded ($`\phi = 0`$), with zero initial displacement, velocity, and potential.
* **Sources**: the manufactured body forces are applied as $`f_1`$ and $`f_3`$ times $`2.30 \times 10^{5}`$ N/m$`^3`$, and the space charge density is applied as $`-\bar{q}`$ times $`2.33 \times 10^{-4}`$ C/m$`^3`$, over the whole domain.
* **Mesh and solver**: the physics-controlled default mesh (24,912 triangular elements with quadratic Lagrange shape functions, 150,675 degrees of freedom) and the default time-dependent solver.
* **Output**: every 25 ns from 0 to 5 $`\mu`$s (201 times), along the line $`x_3 = 9`$ mm at 5,000 equispaced points ($`x_1 = 0.001`$ to $`9.999`$ mm).

### Settings shared by all studies
* **Network**: 7 hidden layers of 150 neurons with Tanh activations, three output heads ($`\hat{u}_1`$, $`\hat{u}_3`$, $`\hat{\phi}`$), Xavier-uniform initialization, and about 137,000 trainable weights. $`\bar{e}_{15}`$ is a trainable scalar initialized at 0.10 (2.33 C/m$`^2`$, an 86% error). The constrained network multiplies its outputs by $`\mathcal{D}_{bc}\,t^2 = x_1(1-x_1)\,x_3(1-x_3)\,t^2`$.
* **Optimization**: Adam (default betas) with a cosine annealing learning rate from $`10^{-3}`$ to $`10^{-5}`$, followed by L-BFGS with a strong-Wolfe line search, history size 100, and tolerances $`10^{-7}`$ (gradient) and $`10^{-9}`$ (function change). The loss is $`\mathcal{L}_{PDE} + \lambda\,\mathcal{L}_{Data}`$ with $`\lambda = 5000`$.
* **Noise**: additive white Gaussian noise at 30 dB (power SNR), drawn independently for each field component.
* **Precision**: float32 throughout, except that the manufactured forcing in `Baseline/` and `Ablation-study/` is computed in float64 and then cast to float32.

### Settings that differ between studies
| Study | Observations | Collocation pool | Adam stage | L-BFGS stage |
|---|---|---|---|---|
| MMS (`MMS-framework/`) | 5,000 random space-time points on the plane $`x_3 = 9`$ mm, all used every step | 25,000 points, $`0 \le \bar{t} \le 1`$; minibatch of 5,000 | 15,000 steps | at most 1,500 iterations (1,875 evaluations), learning rate 0.1, first 15,000 collocation points and all observations |
| FEM (`FEM-framework/`) | 5,000 points $`\times`$ 201 times from the COMSOL export; minibatch of 2,000 | 25,000 points, $`0 \le \bar{t} \le 0.875`$; minibatch of 5,000 | 15,000 steps | at most 1,250 iterations, learning rate 1, 15,000 collocation points and a fixed random subset of 5,000 observations |
| Noise sweep (`SNR-sweep/`) | as FEM; minibatch of 2,000 | as FEM; minibatch of 4,000 | 12,000 steps (cosine schedule over 12,000 steps) | at most 500 iterations, learning rate 1, 15,000 collocation points and 5,000 observations |
| Baselines (`Baseline/`) | 5,000 random points on $`x_3 = 9`$ mm, full batch | 25,000 points, $`0 \le \bar{t} \le 1`$, full batch, plus 5,000 boundary and 5,000 initial-time points | 15,000 steps | at most 1,500 iterations, learning rate 0.1, full batch |
| Ablation (`Ablation-study/`) | as MMS | as MMS; minibatch of 5,000 | 15,000 steps | as MMS |

The FEM data are scaled before training: displacements are converted from mm to the reference length scale (multiplied by $`10^{6}`$, with $`U_{ref} = 1`$ nm), the potential is divided by $`\Phi_{ref} = U_{ref}\,e_{33}/\varepsilon_{33}`$, and time is divided by $`t_{ref} = L_{ref}\sqrt{\rho/c_{44}} = 5.71\ \mu`$s with $`L_{ref} = 10`$ mm.

### Seeds
* **MMS and FEM**: `main.py` sets the seed to 42. The five runs reported for each study were made by changing the seed in the script by hand between runs. The data weight $`\lambda = 5000`$ is a constant in the loss line of the script, so the $`\lambda`$ sensitivity study was run by editing that constant.
* **Noise sweep**: the seed of each run is the system clock time plus the run index, so a sweep cannot be repeated exactly. Each of the 9 SNR levels (40, 35, 30, 25, 20, 15, 10, 5, 0 dB) is run 5 times, and each run draws a fresh noise realization.
* **Baselines and ablation**: seeds 1 to 5 for every configuration. A seed fixes the initial weights, the collocation points, the observations, and the noise, and the same five seeds are used for every formulation.

### Outputs
* `Baseline/` writes `Baseline-Results.csv`, one `.npz` file per run in `Baseline-Runs/`, and `Baseline_Trajectories.png`.
* `Ablation-study/` writes `Ablation-Results.csv`, one `.npz` file per run in `Ablation-Runs/`, and `Ablation_Trajectories.png`.
* Each results CSV has one row per run with the $`e_{15}`$ after Adam and at the end, the percentage errors, the number of L-BFGS iterations and closure evaluations, the relative $`L^2`$ errors of $`u_1`$, $`u_3`$, and $`\phi`$ on 20,000 held-out points, the RMS boundary values and initial rate, the RMS Gauss-law residual, and the run time (the ablation file also has the early-time residual for $`t \le 0.05`$). The summary printed at the end is the mean and the sample standard deviation ($`N-1`$) over the five seeds.
* Each `.npz` file holds the $`e_{15}`$ trajectory for the Adam and L-BFGS stages and the loss terms, plus the adaptive weights and gradient norms for baseline A.

### Expected results
Errors are the mean and sample standard deviation ($`N-1`$) of the absolute percentage error in $`e_{15}`$ (true value 17.0 C/m$`^2`$) at 30 dB noise. The full tables are in the manuscript.

| Study | Mean $`e_{15}`$ (C/m$`^2`$) | Mean error (%) |
|---|---|---|
| Baseline A (adaptive weights) | 25.785 | $`51.7 \pm 31.3`$ (fails in 4 of 5 seeds) |
| Baseline B (fixed weights) | 17.144 | $`0.849 \pm 0.245`$ |
| Ablation C1 ($`\mathcal{D}_{bc}\,t^2`$, paired seeds) | 17.002 | $`0.458 \pm 0.171`$ |
| Ablation C2 | 17.072 | $`0.515 \pm 0.165`$ |
| Ablation C3 | 17.028 | $`0.163 \pm 0.054`$ |
| Ablation C4 | 17.011 | $`0.145 \pm 0.130`$ |
| MMS, original runs ($`\lambda = 5000`$) | 16.981 | $`0.444 \pm 0.229`$ |
| FEM, 30 dB (noise-sweep entry) | 16.810 | $`1.189 \pm 0.651`$ |

The $`\lambda`$ study on the MMS problem gives mean errors of $`1.497 \pm 0.750`$ ($`\lambda = 1000`$), $`0.952 \pm 0.219`$ ($`\lambda = 2500`$), $`0.444 \pm 0.229`$ ($`\lambda = 5000`$), and $`0.175 \pm 0.045`$ ($`\lambda = 10000`$). As a quick check of the paired runs, the final $`e_{15}`$ for seed 1 was 26.236 (A), 17.211 (B), 16.910 (C1), 17.097 (C2), 17.027 (C3), and 17.007 (C4) C/m$`^2`$.

GPU runs are not bitwise repeatable, and L-BFGS amplifies small round-off differences, so a rerun should agree with these values within the run-to-run spread but not digit for digit.
